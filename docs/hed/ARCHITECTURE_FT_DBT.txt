## 🔄 Data Flow Details

### 1. Fivetran Sync
- **Frequency**: Configured in Fivetran (hourly, daily, etc.)
- **Destination**: `HOL_DATABASE.INDUSTRIES_HIGHER_EDUCATION.HED_RECORDS`
- **Data**: Student academic, engagement, and retention metrics

### 2. dbt Source Definition
```yaml
# _hed__sources.yml
sources:
  - name: hed
    database: "{{ var('hed_source_database') }}"     # HOL_DATABASE
    schema: "{{ var('hed_source_schema') }}"         # INDUSTRIES_HIGHER_EDUCATION
    tables:
      - name: hed_records
        identifier: "{{ var('hed_source_table') }}"  # HED_RECORDS
```

### 3. dbt Models (Independent Reads)
All 5 models independently query the source table:
```sql
with source_data as (
  select * from {{ source('hed', 'hed_records') }}
),
-- Transform the data
-- ...
```

### 4. View Creation
- **Schema**: `INDUSTRIES_EDUCATION` (configured in dbt_project.yml)
- **Materialization**: `view` (query-on-demand, no storage)
- **Naming**: `VW_HED_[purpose]` convention

### 5. View Consumption
Users query the views directly in Snowflake:
```sql
SELECT * FROM HOL_DATABASE.INDUSTRIES_EDUCATION.VW_HED_STUDENT_SUCCESS_KPI;
```

## 🏛️ Multi-Industry Architecture

Your project supports multiple industries with consistent patterns:

```
HOL_DATABASE
│
├── INDUSTRIES_HEALTHCARE (CDS)
│   └── CDS_RECORDS (source)
│       ↓
│   INDUSTRIES_HEALTHCARE (schema)
│       ├── VW_CDS_PATIENT_OUTCOMES_KPI
│       ├── VW_CDS_TREATMENT_EFFECTIVENESS
│       ├── VW_CDS_CLINICAL_TRIAL_PERFORMANCE
│       ├── VW_CDS_DATA_QUALITY
│       └── VW_CDS_HIGH_RISK_PATIENTS
│
└── INDUSTRIES_HIGHER_EDUCATION (HED)
    └── HED_RECORDS (source)
        ↓
    INDUSTRIES_EDUCATION (schema)
        ├── VW_HED_STUDENT_SUCCESS_KPI
        ├── VW_HED_RETENTION_RISK_ANALYSIS
        ├── VW_HED_PROGRAM_PERFORMANCE
        ├── VW_HED_ENGAGEMENT_ANALYTICS
        └── VW_HED_DATA_QUALITY
```

**Future industries** (AGR, MET, FTS, etc.) will follow the same pattern:
- Source table in `INDUSTRIES_[NAME]` schema
- Models in `models/[code]/` folder
- Output views in `industries_[name]` schema

## 🔧 Configuration Flow

### dbt_project.yml
```yaml
models:
  dbt_industries_views:
    hed:
      +schema: industries_education  # Target schema for views
      +materialized: view            # Create as views, not tables
      +tags: ['hed', 'education']    # Enable tag-based selection
```

## 🎯 Execution Flow

### Full Run
```bash
dbt run --select hed
```

1. dbt reads `dbt_project.yml` for configuration
2. dbt reads `_hed__sources.yml` for source definition
3. dbt compiles SQL files, substituting variables
4. dbt executes SQL in Snowflake:
   ```sql
   CREATE OR REPLACE VIEW INDUSTRIES_EDUCATION.VW_HED_STUDENT_SUCCESS_KPI AS
   WITH source_data AS (
     SELECT * FROM HOL_DATABASE.INDUSTRIES_HIGHER_EDUCATION.HED_RECORDS
   ),
   -- ... rest of SQL
   ```
5. Views created in `INDUSTRIES_EDUCATION` schema

### Selective Runs
```bash
# By tag
dbt run --select tag:hed,tag:analytics

# By model name
dbt run --select vw_hed_student_success_kpi

# By folder
dbt run --select hed

# By tag combination
dbt run --select tag:data_quality
```

## 📊 Model Dependencies

All HED models are **independent** (no inter-model dependencies):

```
HED_RECORDS (source)
    │
    ├── vw_hed_student_success_kpi
    ├── vw_hed_retention_risk_analysis
    ├── vw_hed_program_performance
    ├── vw_hed_engagement_analytics
    └── vw_hed_data_quality
```

**Benefits:**
- Can run models in any order
- Failure of one model doesn't affect others
- Easy to test and debug individual models
- Simple parallel execution

## 📈 Performance Characteristics

### View Materialization
- **Storage**: None (views don't store data)
- **Query Time**: Executes underlying SQL on each query
- **Freshness**: Always up-to-date with source table
- **Cost**: Compute cost per query execution

### Alternative: Table Materialization
For frequently-queried views with 1M+ rows:
```yaml
vw_hed_student_success_kpi:
  +materialized: table
  +post-hook: "CREATE INDEX IF NOT EXISTS idx_student ON {{ this }} (student_id)"
```

**Tradeoffs:**
- **Pro**: Faster query performance
- **Pro**: Reduced compute cost for frequent queries
- **Con**: Uses storage
- **Con**: Not real-time (updated on dbt run)

```yaml
vars:
```

```yaml
# In dbt_project.yml
hed:
  +schema: "{{ 'dev_education' if target.name == 'dev' else 'industries_education' }}"
```

## 📊 Monitoring & Observability

### Built-In Monitoring
- **Data Quality View**: Check composite quality score daily
- **dbt Logs**: Track model execution time and success/failure
- **Snowflake Query History**: Monitor view query patterns

### Recommended Alerts
```sql
-- Alert if data quality drops below 85
SELECT * FROM VW_HED_DATA_QUALITY
WHERE COMPOSITE_QUALITY_SCORE < 85;

-- Alert if data is stale (>24 hours old)
SELECT * FROM VW_HED_DATA_QUALITY
WHERE HOURS_SINCE_LAST_UPDATE > 24;
```
